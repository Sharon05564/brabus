# Brabus — On-Device Document Intelligence Assistant

> A privacy-focused iOS machine learning prototype that scans or accepts document text, classifies the document type using an on-device Core ML model, extracts actionable details, and recommends next steps — entirely on-device.

---

## Why I Built This

I'm studying computer science with a focus on machine learning and iOS development, and I wanted to build something that brings those two disciplines together in a way that feels useful and real — not just a toy model predicting flowers.

Brabus is my answer to the question: *What would a human-centered, privacy-first AI feature on iPhone actually look like?*

The project was designed to demonstrate the skills Apple and similar companies look for in an AIML internship candidate:

- **On-device intelligence** — The model runs entirely on the device. No API call, no server round-trip, no data leaving the phone.
- **Privacy-preserving ML** — Users can scan sensitive documents (scholarship letters, receipts, job applications) without their text being sent anywhere.
- **Full ML pipeline** — From synthetic dataset generation to PyTorch training to Core ML conversion to SwiftUI integration.
- **Human-centered output** — The goal isn't just a label; it's a structured result the user can act on.

## Features

| Feature | Description |
|---|---|
| Vision OCR | Reads text from photos using `VNRecognizeTextRequest` |
| Pasted text fallback | Works without a camera — paste any document text |
| Document classification | Predicts one of 7 document categories on-device |
| Feature extraction | Extracts dates, emails, phone numbers, dollar amounts, action words |
| Action recommendation | Suggests a concrete next step based on document type + extracted entities |
| Session history | Keeps a scrollable log of analyses with full detail view |
| scikit-learn baselines | TF-IDF + Logistic Regression and LinearSVC for comparison |
| PyTorch classifier | OOP numeric-feature feedforward network |
| Core ML conversion | PyTorch → `.mlmodel` via coremltools for on-device inference |
| Model evaluation | Accuracy, precision, recall, F1, confusion matrix |
| Privacy-first design | Zero external API calls; all inference on-device |

## How to Run the ML Pipeline

```bash
cd ml
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# Step 1 — Generate the synthetic dataset (creates ml/data/document_dataset.csv)
python generate_dataset.py

# Step 2 — Train scikit-learn baseline models
python train_sklearn.py

# Step 3 — Train the PyTorch numeric-feature classifier
python train_pytorch.py

# Step 4 — Convert PyTorch model to Core ML (requires macOS + coremltools)
python convert_to_coreml.py

# Step 5 — Reload saved models and confirm evaluation
python evaluate.py
```

**Note on convert_to_coreml.py:** coremltools works best on macOS. The script
is written correctly and will convert the model if run in a macOS environment
with coremltools installed. On Linux or Windows it will install but may have
limited compatibility.

## How to Run the iOS App

1. **Run the Python pipeline** above to generate `BrabusDocumentClassifier.mlmodel`
   in `ios/Brabus/Models/`.

2. **Open Xcode** (14 or later recommended).

3. **Create a new SwiftUI project** named `Brabus` if you don't have one,
   or use an existing project.

4. **Add all Swift source files** from `ios/Brabus/` to the project:
   - `BrabusApp.swift`
   - `ContentView.swift`
   - `Views/HomeView.swift`
   - `Views/ScanView.swift`
   - `Views/AnalyzeView.swift`
   - `Views/HistoryView.swift`
   - `Views/AboutView.swift`
   - `ML/MLModelManager.swift`
   - `ML/DocumentFeatureExtractor.swift`
   - `Engines/RecommendationEngine.swift`
   - `Models/DocumentModels.swift`

5. **Drag `BrabusDocumentClassifier.mlmodel`** into the Xcode project navigator.
   In the file inspector, make sure the Brabus app target is checked under
   **Target Membership**.

6. **Update normalization constants** in `MLModelManager.swift`:
   Open `ml/models/brabus_pytorch_metadata.json` and copy the
   `normalization_means` and `normalization_stds` arrays into the
   `normMeans` and `normStds` properties.

7. **Build and run** on Simulator (iOS 16+) or a physical device.

> The app includes a heuristic fallback classifier that works even before
> the `.mlmodel` file is added to Xcode, so you can explore the UI immediately.

## Model Details

### Document Labels

| Label | Description |
|---|---|
| `syllabus` | Course syllabi with policies, grading, office hours |
| `assignment_sheet` | Homework or project instructions with rubrics and deadlines |
| `event_flyer` | Event announcements with RSVP, location, speakers |
| `receipt` | Purchase receipts with totals, tax, payment method |
| `scholarship_notice` | Scholarship applications with GPA requirements, deadlines |
| `job_posting` | Job/internship listings with qualifications and salary |
| `general_notes` | Class notes, meeting notes, reminders, brainstorming |

### Numeric Features (12 total)

The PyTorch model and Core ML model are trained on 12 numeric features extracted
by `extract_features.py` (Python) and mirrored in `DocumentFeatureExtractor.swift`
(Swift):

| # | Feature | Description |
|---|---|---|
| 0 | `character_count` | Total characters in document |
| 1 | `word_count` | Whitespace-delimited token count |
| 2 | `sentence_count` | Approximate sentence count |
| 3 | `date_count` | Dates detected (regex) |
| 4 | `email_count` | Email addresses detected |
| 5 | `phone_count` | Phone numbers detected |
| 6 | `dollar_amount_count` | Dollar amounts detected |
| 7 | `action_word_count` | Action words (submit, apply, attend, …) |
| 8 | `education_keyword_count` | Education vocabulary (syllabus, grade, GPA, …) |
| 9 | `job_keyword_count` | Job vocabulary (resume, salary, internship, …) |
| 10 | `receipt_keyword_count` | Receipt vocabulary (total, tax, paid, …) |
| 11 | `deadline_keyword_count` | Deadline phrases (due, deadline, closes, …) |

### Why Numeric Features for Core ML?

TF-IDF models require a vocabulary lookup that is difficult to reproduce exactly
in Swift without shipping the full vocabulary file. Numeric features can be
computed in Swift with the same regex patterns used in Python, so the Swift app
produces identical inputs to what the model was trained on.

The TF-IDF models (Logistic Regression and LinearSVC) are included as baselines
to show the comparison between text-based and feature-based approaches.

### Architecture

```
DocumentClassifier (PyTorch)
  Input:   12 normalized floats
  Layer 1: Linear(12 → 64) → ReLU → Dropout(0.3)
  Layer 2: Linear(64 → 32) → ReLU → Dropout(0.3)
  Layer 3: Linear(32 → 7)
  Output:  7 logits (softmax at inference)

Total parameters: ~1,800
```

## Evaluation

After running `python train_pytorch.py` and `python evaluate.py`, metrics are
saved to `ml/models/brabus_pytorch_metrics.json` and `ml/models/sklearn_metrics.json`.

### Typical Results (synthetic dataset)

Because the training data is synthetic and each class has clear lexical
patterns, both the sklearn and PyTorch models tend to perform well on the
held-out test set. Expect results in roughly this range:

| Model | Accuracy | F1 (weighted) |
|---|---|---|
| Logistic Regression + TF-IDF | ~0.93–0.97 | ~0.93–0.97 |
| LinearSVC + TF-IDF | ~0.94–0.98 | ~0.94–0.98 |
| Logistic Regression + numeric | ~0.75–0.85 | ~0.75–0.85 |
| PyTorch + numeric features | ~0.78–0.88 | ~0.78–0.88 |

The numeric-feature models are weaker than TF-IDF because 12 features carry
less information than thousands of TF-IDF dimensions. However, they are the
models used for on-device inference because they can be reproduced in Swift
without shipping vocabulary files.

### Confusion Matrix

Confusion matrix images are saved to:
- `ml/models/sklearn_confusion_matrix.png`
- `ml/models/brabus_pytorch_confusion_matrix.png`

Common confusions on the synthetic dataset:
- `assignment_sheet` ↔ `syllabus` (both have education keywords and deadlines)
- `scholarship_notice` ↔ `assignment_sheet` (both have deadlines and submission language)
- `general_notes` is sometimes confused with other classes when it contains dates or keywords

### Evaluation Metrics Explained

- **Accuracy**: Fraction of all test samples correctly classified.
- **Precision (weighted)**: Average precision across classes, weighted by class size.
- **Recall (weighted)**: Average recall across classes, weighted by class size.
- **F1 (weighted)**: Harmonic mean of precision and recall; best single metric for imbalanced evaluation.
- **Confusion matrix**: Rows = true labels, Columns = predicted labels. Diagonal = correct predictions.

## Limitations

Being honest about limitations is part of good engineering:

- **Synthetic dataset**: The model is trained on programmatically generated text. Real documents are messier, more varied, and often don't contain the clean keyword signals the synthetic examples do. Real-world accuracy would require a real labeled dataset.
- **OCR accuracy**: `VNRecognizeTextRequest` accuracy depends on image quality, lighting, and font. Low-quality scans may produce garbled text.
- **Seven categories only**: Documents that don't match any of the seven training classes will be misclassified. "Unknown" is not a trained output.
- **Numeric features are lossy**: 12 features summarize a document but lose most of its meaning. A transformer-based text model would generalize much better.
- **No persistence**: Session history is lost when the app closes.
- **Not advice**: Brabus is not legal, financial, academic, or professional advice.
